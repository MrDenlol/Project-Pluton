# Project Pluton — Circuit Lab

Учебная среда на **Rust** для проектирования и моделирования цифровых схем.
Настольный интерфейс — **egui/eframe**, открытый исходный код — **MIT**.
Интерфейс и инструкция на русском языке.

Это самостоятельный учебный проект, вдохновлённый тематикой архитектуры
компьютера. Иллюстрации и тексты из книги Эндрю Таненбаума не копируются.

## Возможности версии 0.1

- Графический редактор: библиотека блоков, соединение портов, перетаскивание,
  масштаб и перемещение поля, инспектор, удаление проводов и блоков, отмена/повтор.
- Вентили AND, OR, XOR, NOT, NAND, NOR; шины от 1 до 64 бит.
- Полусумматор, полный сумматор, многобитные ADD, SUB, MUL, DIV и MUX 4:1.
- D-триггер / регистр до 64 бит; однобитные JK-, T- и SR-триггеры.
- Тактовый генератор, шаг, запуск/пауза, сброс, временные диаграммы.
- Сохранение и загрузка JSON с контролем версии, портов, ширины шин и петель.
- Четыре встроенные схемы и соответствующие файлы в `examples/`.
- Отдельная консольная утилита проверки схем без графического интерфейса.

## Запуск

Если в комплекте есть `circuit-lab.exe`, запустите его двойным щелчком.
Дополнительные файлы примеров не обязательны: схемы также встроены в приложение.

Для сборки из исходников установите Rust через [rustup](https://rust-lang.org/tools/install/).
На Windows нужны C++ Build Tools / Visual Studio с компонентом **Desktop development
with C++** и Windows SDK. На Linux для GUI понадобятся системные пакеты X11/Wayland
и OpenGL; автоматическая проверка Linux настраивается в `.github/workflows/ci.yml`.

```sh
cargo run --release --bin circuit-lab
```

Открыть определённую схему при запуске:

```sh
cargo run --release --bin circuit-lab -- examples/alu64.json
```

Проверки без GUI:

```sh
cargo test --no-default-features
cargo run --no-default-features --bin circuit-check -- examples/alu64.json
cargo run --no-default-features --bin circuit-check -- examples/counter.json 8
```

Сборка и проверки всего проекта:

```sh
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
cargo build --release --bin circuit-lab
```

## Быстрая демонстрация

При запуске открывается **АЛУ · 64 бита** с `A = 42`, `B = 7`.
Выберите блок «Операция 0…3», введите число справа и нажмите «Применить»:

| Код | Операция | Результат |
|---:|---|---:|
| 0 | A + B | 49 |
| 1 | A − B | 35 |
| 2 | A × B | 294 |
| 3 | A ÷ B | 6 |

Выбирайте входы A и B для изменения операндов. Допустимы десятичная запись,
`0xFFFFFFFFFFFFFFFF`, `0b101010`; разделитель `_` игнорируется.
Значения проверяются без преобразования в `float`, поэтому сохраняются все 64 бита.

«Результат» подключён к выходу MUX; «Остаток A % B» показывает остаток деления
при любом коде операции. Выходы Carry/Borrow/Overflow можно подключить к
однобитным индикаторам или посмотреть в инспекторе блока.

## Работа в редакторе

1. Выберите число бит и нажмите нужный блок в библиотеке слева.
2. Нажмите выходной кружок справа у блока, затем входной слева у другого.
   У одного входа один источник; подключение нового заменяет прежний провод.
   Выход может питать несколько входов. Ширины портов должны совпадать.
3. Выберите входной блок и измените значение в инспекторе.
   Комбинационная логика пересчитывается сразу.
4. Перетаскивайте блоки левой кнопкой; средней перемещайте поле;
   колесом меняйте масштаб. «Вписать» показывает всю схему.
5. Правый щелчок по входному порту или «×» в инспекторе удаляет провод.
6. «Шаг» переключает генераторы. **Один шаг — половина периода CLK**.
   При начальном CLK=0 захват происходит на шагах 1, 3, 5 и т. д.
7. «Запуск» делает шаги с заданной частотой. «Сброс» останавливает выполнение,
   обнуляет память и CLK и очищает историю сигналов, сохраняя значения входов.
8. «Сохранить» / «Открыть» работают с файлами JSON. Файл содержит структуру,
   координаты и значения входов; состояние симуляции и временные диаграммы
   не сохраняются. При загрузке Q и CLK начинаются с нуля.

Горячие клавиши: Ctrl+S, Ctrl+O, Ctrl+Z, Ctrl+Y, Delete, Esc.
Отмена/повтор относятся к редактированию схемы и сбрасывают симуляцию.
Перед закрытием или заменой изменённой схемы приложение предлагает её сохранить.

## Правила модели

- Идеальные цифровые сигналы, без задержек распространения и метастабильности.
- `X` означает неподключённый вход или неизвестное значение.
  Для шины неизвестность задаётся целиком, без маски отдельных неизвестных битов.
- Арифметика **беззнаковая**. Результат ограничен шириной шины:
  для 64 бит это остаток по модулю 2⁶⁴.
- ADD выдаёт перенос, SUB — заём, MUL — признак ненулевой старшей части
  произведения. Это не флаги переполнения знаковой арифметики.
- DIV возвращает целую часть и остаток. Деление на ноль выдаёт `DIV/0`.
  Ошибка невыбранного входа MUX не портит выбранный результат.
- Все триггеры переключаются по **переднему фронту 0 → 1**.
  D копирует D; JK реализует hold/reset/set/toggle; T переключает Q при T=1.
  SR — **тактируемый триггер**, не асинхронная защёлка; S=R=1 даёт `SR!`.
- Перед фронтом рассчитываются входы всех триггеров. Новые Q публикуются
  одновременно, затем заново рассчитывается комбинационная часть.
  Это предотвращает зависимость от порядка блоков при общем CLK.
- Для последовательных схем используйте общий генератор CLK. Каскадные
  тактовые домены и моделирование задержек не входят в версию 0.1.
- Комбинационные петли отклоняются. Обратная связь через триггер разрешена:
  пример — счётчик `Q → ADD → D`.
- До 4096 блоков, 16384 проводов, 8 МБ на файл. Формат версии 1.

## Архитектура проекта

| Модуль | Назначение |
|---|---|
| `model.rs` | Блоки, порты, провода, валидация и порядок вычислений |
| `arithmetic.rs` | Полный сумматор, ripple-carry, вычитание, shift-and-add, restoring division |
| `simulator.rs` | Расчёт сигналов, память, одновременный захват по фронту |
| `storage.rs` | Проверяемая загрузка и сохранение через временный файл |
| `demos.rs` | Четыре демонстрации |
| `ui.rs` | Графический редактор и управление симуляцией |
| `src/bin/check.rs` | Консольная проверка / экспорт примеров |
| `tests/core.rs` | Таблицы истинности, арифметика, триггеры, файлы, некорректные схемы |

Симулятор не зависит от GUI: `--no-default-features` исключает eframe и rfd.
Подробный план и критерии приёмки — в [PLAN.md](PLAN.md).

## Дальнейшее развитие

Иерархические подсхемы, разветвители шин, RAM/ROM, знаковые операции,
асинхронные защёлки, задержки элементов и VCD-экспорт — отдельные следующие
этапы. В этой версии арифметические блоки отображаются как функциональные
узлы; раскрытия 64-битного АЛУ до каждого вентиля пока нет.
