# Участие в разработке

1. Создайте ветку для конкретного исправления или функции.
2. Не смешивайте модель цифровой логики с кодом интерфейса.
3. Изменение поведения элемента сопровождайте проверкой таблицы истинности
   или последовательности тактов. Используйте фиксированные данные.
4. Перед отправкой изменений выполните:

```sh
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

5. Опишите изменённое поведение, способ воспроизведения и проверку.

Изменения формата схем требуют явной миграции и обновления версии.
Не добавляйте в репозиторий материалы из учебников без разрешения правообладателя.
